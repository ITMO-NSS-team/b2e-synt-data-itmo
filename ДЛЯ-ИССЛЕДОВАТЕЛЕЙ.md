# Стенд B2E (ИТМО) — краткая инструкция

## Доступ

Всё закрыто одним HTTP Basic на прокси. Открытых точек входа нет, включая health-check.

```
Логин:  researcher
Пароль: см. у администратора стенда
База:   https://89.169.170.195:8443
```

Сертификат самоподписанный (у хоста нет DNS-имени), поэтому браузер покажет
предупреждение, а `curl` требует флаг `-k`. Это ожидаемо.

| Что | Адрес |
|---|---|
| Точка входа | `https://89.169.170.195:8443/` |
| API агента (Swagger) | `https://89.169.170.195:8443/agent/docs` |
| Research API (Swagger) | `https://89.169.170.195:8443/research/docs` |
| Админка (одобрение навыков) | `https://89.169.170.195:8443/admin/` |
| Phoenix (трассы) | `https://89.169.170.195:8443/phoenix/` |
| Telegram-бот | `@B2E_ITMO_test_bot` |

У админки собственный логин и пароль, отдельно от `researcher`.

Эмулятор Heimdall наружу **не опубликован** намеренно: это слой данных, к нему
ходит только агент.

## Два способа работы

**Диалог** — `/agent`: одна сессия, вопрос-ответ, память между сообщениями.
**Пакетный прогон** — `/research`: эксперимент по списку вопросов и сотрудников,
метрики против эталонного банка вопросов.

Дальше `$B` = `https://89.169.170.195:8443`, `-u researcher:ПАРОЛЬ`.

### Диалог с агентом

Создать сессию:

```sh
curl -k -u researcher:ПАРОЛЬ -X POST $B/agent/sessions \
  -H 'Content-Type: application/json' \
  -d '{"employee_id":"9877478","config_ref":"agent_config_interactive"}'
```

Ответ содержит `session_id` и `fingerprint` — слепок условий прогона
(модель, версия промпта, хеш снапшота данных, включены ли каверзы). Два прогона
с одинаковым `condition_id` сравнимы между собой; с разным — нет.

`config_ref`:
- `agent_config_interactive` — сессия помнит диалог (по умолчанию у бота);
- `agent_config` — каждое сообщение начинается с нуля (пакетный режим).

Задать вопрос:

```sh
curl -k -u researcher:ПАРОЛЬ -X POST $B/agent/sessions/ses_XXXX/messages \
  -H 'Content-Type: application/json' \
  -d '{"content":"Сколько сотрудников в моём подразделении?"}'
```

Ход выполнения: `GET $B/agent/sessions/ses_XXXX/progress`

### Пакетный эксперимент

```sh
curl -k -u researcher:ПАРОЛЬ -X POST $B/research/experiments \
  -H 'Content-Type: application/json' \
  -d '{"name":"pilot-1","employee_ids":["9877478"],"basket_id":"...","max_usd":5}'
```

Обязательны `name` и `employee_ids`. Вопросы задаются либо списком `questions`,
либо ссылкой на готовую корзину `basket_id`. `max_usd` и `max_tokens` — предохранители,
ставьте их всегда.

- Статус и метрики: `GET $B/research/experiments/{id}`
- Выгрузка (Parquet/JSONL): `GET $B/research/experiments/{id}/export`
- Остановить: `POST $B/agent/experiments/{id}/kill`

### Трассы и обратная связь

```sh
GET  $B/research/sessions?limit=20        # список сессий
GET  $B/research/traces/{session_id}      # полное дерево спанов
POST $B/research/feedback                 # {"session_id":"...","label":"correct"}
```

Обязательное поле у обратной связи — `label`; она пишется аннотацией в Phoenix и
видна в UI рядом с трассой.

## Права доступа

Агент отвечает от лица сотрудника из `employee_id`. Руководитель видит только
своё подразделение и всё, что под ним; в текущем корпусе это ~21 человек.
Вопросы «по всей компании» требуют роли HR — сейчас она выдана только
`9877478`.

Отказы 403 — это не поломка, а измеряемое поведение: на них построена целая
категория вопросов.

## Что важно знать про данные

Корпус синтетический, 3 000 человек (`data-small`). Каверзы включены
(`traps_enabled=true`), профиль задержек — `realistic`. Оба переключаются на лету
из админки, но переключение меняет `condition_id`: прогоны до и после
несопоставимы.

## Если что-то не отвечает

```sh
curl -k -u researcher:ПАРОЛЬ $B/agent/healthz
curl -k -u researcher:ПАРОЛЬ $B/research/healthz
```

`healthz` агента показывает режим модели, доступность Heimdall, экспорт трасс и
готовность харнесса. Логи и состояние сервисов — `make ps`, `make logs`
в каталоге стенда.
