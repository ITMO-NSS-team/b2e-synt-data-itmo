# b2e-synt-data — синтетический HR-корпус в форме API Heimdall

Генератор синтетических данных для **симуляционных экспериментов с B2E-агентом**
(business-to-employee): низкоресурсной LLM, которая помогает сотруднику получить
рекомендации и анализ команды, обращаясь к семантическому слою поверх HR-витрин.

Все данные полностью синтетические. Совпадения с реальными людьми, компаниями
и подразделениями исключены; словари написаны вручную.

```bash
make setup                 # окружение
make catalog OPENAPI=...   # каталог витрин из спецификации OpenAPI
make data-small            # корпус на 3 000 человек (≈25 с, 9 МБ)
make validate              # гейт согласованности
make doc                   # HTML-документация витрин
make serve                 # эмулятор Heimdall на :8080
```

---

## Что это даёт

| | |
|---|---|
| **37 витрин** каталога Heimdall, **4 599 колонок**, **148 метрик**, 7 схем | ни одной пустой витрины, кроме одной объявленной |
| **~300 000 сотрудников** в оргструктуре из ~32 500 подразделений | 5 уровней, реальная цепочка подчинения |
| **90 вузов, 62 курса, ~1 900 фамилий** с частотами по Ципфу | содержательные значения вместо `«промежуточный institute_name 61»` |
| Каналы `/mcp`, `/v2/mcp`, `/orion/mcp`, REST-зеркало | движок запросов Heimdall переиспользован как есть |
| Гейт из 22 инвариантов | сборка падает, если согласованность нарушена |

## Зачем это понадобилось

Предшественник — HR-песочница фабрики скиллов — заложил правильный фундамент
(каталог как источник истины, латентные факторы, детерминизм). Но его корпус
нельзя было использовать для симуляции: измерения на его собственных данных
показали, что **витрины заполнялись независимо друг от друга**.

| Дефект | Было | Стало |
|---|---|---|
| Один `person_id` — разные имена на разных витринах | совпадение **0/3000** | **100%**, проверяется гейтом |
| Фамилия против собственного ФИО в той же строке | **30/3000** | **100%** |
| Массивы образования выровнены позиционно | **4/3000** | **100%** |
| Девять компетенций различимы внутри человека | разброс **0.0** | разброс **1.14** |
| Оценка A–E связана с грейдом | corr **0.035** | corr **0.36** |
| Грейд не сводится к возрасту | corr(возраст, грейд) **0.88** | **0.40** |
| Доля руководителей | **62.5%** | **9.4%** |
| Испытательный срок | константа **0** | **1.9%** |
| Руководители — реальные сотрудники | ссылок нет | **100%** |
| Непустых витрин | **18/37** | **36/37** |

Полный разбор — [docs/design.md](docs/design.md).

## Как устроено

```
catalog/snapshot.json      каталог витрин, собранный из спецификации OpenAPI
b2e/gen/rng.py             адресуемая случайность: значение = f(seed, координата)
b2e/gen/dicts.py           словари: вузы, курсы, должности, города, блоки
b2e/gen/names.py           морфология имени: род, склонение, отчество по правилу
b2e/gen/org.py             дерево организации и штатные позиции
b2e/gen/population.py      ядро популяции, факторная модель
b2e/gen/blocks.py          группы параллельных массивов
b2e/gen/resolve.py         цепочка разрешения колонки  ← центральный модуль
b2e/gen/marts.py           строковые пространства всех 37 витрин
b2e/store.py               гибридное хранилище: диск + процедурный хвост
b2e/validate.py            гейт согласованности
b2e/htmldoc.py             HTML-документация
heimdall/                  эмулятор API (переиспользован)
truth/                     скрытые факторы и gold-метки (через API недоступны)
```

Три решения, на которых держится всё остальное:

**Витрина — проекция, а не генератор.** Есть одна популяция; любая колонка любой
витрины проходит цепочку: переопределение витрины → атрибут человека → атрибут
оргединицы → группа массивов → процедурный заполнитель. Новая витрина не требует
маппинга, а новый алиас чинит класс колонок сразу везде.

**Гибридное хранилище.** 300 000 × 4 599 = 1,4 млрд ячеек — столько не
материализовать. На диск идут ~800 осмысленных колонок; хвост вычисляется на
чтении из координаты `(seed, витрина, колонка, строка)` — детерминированно,
одинаково в любом процессе. Корпус на 300 000 человек занимает около 1 ГБ.

**Квантильное отображение вместо обрезки.** Скрытая величина отображается на
заданное распределение по рангу: маргиналы получаются точными, связь со скрытым
фактором сохраняется, свалки на границе диапазона не возникает.

## Каверзы

Ситуации, где запрос возвращает 200 OK и неверный ответ, объявлены в
[`b2e/traps.py`](b2e/traps.py) и включаются флагом — чтобы эксперимент можно было
провести с ними и без них и приписать разницу именно им.

## Для чего это инструмент

Симулятор построен под четыре исследовательских вопроса о B2E-агенте, который
**не может генерировать и исполнять код на лету** и работает только через API и
предопределённые скиллы: снижение галлюцинаций, скорость ответа, структура
долговременной памяти, и обучение флота агентов на обратной связи.
См. [docs/research-agenda.md](docs/research-agenda.md).
