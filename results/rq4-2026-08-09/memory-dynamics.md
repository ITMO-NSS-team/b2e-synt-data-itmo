# RQ4 — memory dynamics, epoch by epoch

A1 is absent by design: it carries no memory, which is the point of it. `built_after_epoch` is the epoch whose episodes produced the pack; `active_in_epoch` is when the agent read it.

**after epoch 0**
- `+` *pitfall* — При поиске единичного атрибута (grade, статус) обработать null-значения явно. Не предполагать значения по умолчанию; пересчитать логику фильтрации по полям.
- `+` *pitfall* — Перед отказом с ссылкой на чувствительность данных проверить наличие информации через API. Допускаются запросы агрегирующего характера, если доступ не запрещён.
- `+` *api_mechanic* — При вопросах о сотрудниках явно валидировать права доступа перед ответом. Отсутствие явного разрешения = отказ, даже если данные в системе есть.

**after epoch 1**
- `+` *pitfall* — При поиске атрибута сотрудника обработать null явно. Не применять значения по умолчанию; возвращать только то, что в системе.
- `+` *pitfall* — Не отказывать только потому, что вопрос неоднозначен. Попробовать интерпретировать и ответить, если данные доступны через API.
- `+` *api_mechanic* — При расчётах по подразделениям (медиана, среднее) явно фильтровать null-значения перед агрегацией. Валидировать логику группировки: каждый объект в одной группе.

**after epoch 2**
- `+` *pitfall* — Неоднозначный вопрос требует явного отказа или уточнения, не попытки интерпретировать и ответить приблизительно.
- `+` *method* — Доля/статистика по категориям — агрегирующий запрос; отвечать, даже если поименные данные закрыты.
- `+` *api_mechanic* — При агрегации по категориям (подсчёт, доля): явно фильтровать null, проверить знаменатель и корректность группировки.
- `−` *pitfall* — Не отказывать только потому, что вопрос неоднозначен. Попробовать интерпретировать и ответить, если данные доступны через API.
- `−` *pitfall* — Перед отказом проверить доступность через API. Агрегирующие запросы допускаются, даже если поименные данные закрыты; не отказывать только потому, что вопрос кажется чувствительным.

**after epoch 3**
- `+` *pitfall* — При сравнении атрибутов: явно обработать null, не применять значения по умолчанию; правильная логика сравнения.
- `+` *pitfall* — Перед отказом 'нет данных': явно проверить API — может быть, данные есть но null. Отличать отсутствие данных от access control.
- `+` *method* — Агрегированные метрики (доля, подсчёт, средние): отвечать даже если доступ закрыт на поименные данные.

**after epoch 4**
- `+` *api_mechanic* — При ранжировании топ-N: фильтровать null, отсортировать по метрике, вернуть ровно N элементов (или меньше). Проверить порядок сортировки.
- `+` *api_mechanic* — Подсчёт объектов выполним при доступе к самим объектам: фильтровать null и посчитать остаток. Отказ только при полной недоступности источника.
- `−` *pitfall* — При сравнении атрибутов: явно обработать null, не применять значения по умолчанию; правильная логика сравнения.

**after epoch 5**
- `+` *method* — На агрегированные вопросы (подсчёты, медиана, топ-N) отвечай на основе доступного, не отказывай. Отказ только при полной недоступности источника.
- `−` *pitfall* — При поиске атрибута или подсчёте по категориям: явно обрабатывать null, фильтровать перед группировкой, не применять значения по умолчанию.
- `−` *pitfall* — При поиске атрибута сотрудника обработать null явно. Не применять значения по умолчанию; возвращать только то, что в системе.
- `−` *api_mechanic* — При ранжировании топ-N: фильтровать null, отсортировать по метрике, вернуть ровно N элементов (или меньше). Проверить порядок сортировки.
- `−` *api_mechanic* — Подсчёт объектов выполним при доступе к самим объектам: фильтровать null и посчитать остаток. Отказ только при полной недоступности источника.
- `−` *api_mechanic* — Агрегация по категориям: явно вычислить числитель (объекты в категории) и знаменатель (базовое множество), фильтровать null перед делением, убедиться в непересечении групп.
- `−` *method* — Агрегированные метрики (доля, подсчёт, средние): отвечать даже если доступ закрыт на поименные данные.
- `−` *method* — При расчёте доли: явно определить числитель (объекты в целевой категории) и знаменатель (все объекты); фильтровать null в обоих перед делением; проверить непересечение групп.

**after epoch 6**
- `+` *pitfall* — Перед отказом проверь: вернула ли API ошибку доступа или просто отсутствует поле? Попробуй альтернативные источники перед полным отказом.
- `−` *pitfall* — Перед отказом 'нет данных': явно проверить API — может быть, данные есть но null. Отличать отсутствие данных от access control.
- `−` *pitfall* — Неоднозначный вопрос требует явного отказа или уточнения, не попытки интерпретировать и ответить приблизительно.

**after epoch 7**
- `+` *method* — На амбигвус вопросы не отказывай — запроси уточнение: срез данных, определения термов, интерпретацию. Предложи вариант вместо молчания.
- `−` *pitfall* — Перед отказом проверь: вернула ли API ошибку доступа или просто отсутствует поле? Попробуй альтернативные источники перед полным отказом.

- `+` *api_mechanic* — Для подсчётов используй встроенные возможности API для агрегации вместо загрузки и обработки всех записей. Проверь документацию на параметры для группировки.

- `+` *api_mechanic* — При неправильном значении проверь параметры фильтра, интерпретацию формата ответа и правильность вычислений на данных API.
- `−` *api_mechanic* — При поиске убедись, что правильно используешь параметры фильтра в запросе API и корректно интерпретируешь формат результатов.

- `+` *api_mechanic* — При неправильном значении проверь парсинг структуры ответа, полноту данных, типы и преобразования. Причина часто в неправильной интерпретации, а не в самом API.
- `−` *api_mechanic* — При неправильном значении проверь параметры фильтра, интерпретацию формата ответа и правильность вычислений на данных API.

**after epoch 3**
- `+` *api_mechanic* — При top-N запросах убедись в правильности сортировки, полноте выборки и том, что N соответствует запросу. Ошибки часто в логике выбора top элементов.

**after epoch 4**
- `+` *pitfall* — Проверь, есть ли реальное ограничение доступа, а не предполагаемое. Попытайся запрос, и только API ответ подтвердит отказ, не предположения.
- `+` *api_mechanic* — Для медиан и агрегаций пересчитай результат вручную на полной выборке, исключая пропуски. Ошибка часто в обработке граничных случаев.
- `+` *api_mechanic* — При lookup-запросах убедись, что применены правильные фильтры и вернулась полная запись по идентификатору. Проверь, не обрезается ли выборка.
- `−` *api_mechanic* — При top-N запросах убедись в правильности сортировки, полноте выборки и том, что N соответствует запросу. Ошибки часто в логике выбора top элементов.

- `−` *api_mechanic* — Для медиан и агрегаций пересчитай результат вручную на полной выборке, исключая пропуски. Ошибка часто в обработке граничных случаев.
- `−` *api_mechanic* — При lookup-запросах убедись, что применены правильные фильтры и вернулась полная запись по идентификатору. Проверь, не обрезается ли выборка.

**after epoch 6**
- `+` *api_mechanic* — Для count_by_grade: проверь что фильтры по статусам и уровням применены перед GROUP BY; пересчитай результат по полной выборке из API.
- `−` *api_mechanic* — Для exists_senior: проверь полноту данных по иерархии и уровням, убедись что фильтры включают весь нужный набор записей перед выводом результата.

**after epoch 7**
- `+` *pitfall* — Unnecessary refusal: попытайся запросить данные через API перед отказом, даже если вопрос кажется невозможным. Откажи только после явной ошибки доступа от API.
- `+` *api_mechanic* — Count_heads: убедись что считаешь все записи из выборки, не подмножество; проверь правильность применения фильтров; результат должен соответствовать полной выборке.
- `−` *api_mechanic* — Для count_by_grade: проверь что фильтры по статусам и уровням применены перед GROUP BY; пересчитай результат по полной выборке из API.

**after epoch 0**

- `+` *pitfall* — При подсчете персонала убедитесь, что агрегируете все уровни иерархии и не пропускаете записи. Неправильная фильтрация или неполный обход структуры приводит к недосчету.
- `+` *method* — При ранжировании убедитесь, что сортируете по правильному полю и выбираете именно N лучших, а не первых N из исходного набора.
- `+` *method* — Для расчета долей: (значение_для_группы / общее_значение). Убедитесь, что знаменатель включает все категории, а не только подмножество.

**after epoch 1**
- `+` *pitfall* — При access_control проверьте, доступны ли данные; если доступны, дайте ответ; отказ только если данные действительно недоступны или есть явное ограничение.
- `+` *method* — При подсчёте по категориям убедитесь, что включены все группы; отсутствующие в результате категории либо имеют нулевое значение, либо ошибка в выборке.

**after epoch 2**
- `+` *pitfall* — При отсутствии данных в источнике не отказывайте; проверьте смежные источники или сообщите об отсутствии честно вместо отказа.
- `+` *method* — При среднем по единицам фильтруйте записи для каждой единицы; проверьте полноту фильтра и отсутствие случайных пропусков.
- `+` *method* — При сравнении групп убедитесь, что сравниваются одинаковые атрибуты; проверьте сопоставимость фильтров и источников.

**after epoch 3**
- `+` *method* — При медиане по единицам получите отсортированные данные для каждой unit; найдите средний элемент, для чётного количества берите среднее двух средних.

**after epoch 4**
- `+` *method* — Получите через API данные о сотрудниках нужного уровня; ответьте да или нет на основе результата, не отказывайте при отсутствии совпадений.

**after epoch 5**
- `−` *pitfall* — При нечётких вопросах выполните API-запрос с вашей интерпретацией смысла; обязательно попытайтесь ответить на основе запроса, никогда не отказывайте.
- `−` *method* — При медиане по единицам получите отсортированные данные для каждой unit; найдите средний элемент, для чётного количества берите среднее двух средних.
- `−` *method* — Для каждой unit отдельно получите данные через API с фильтром; убедитесь что фильтр применён; среднее = сумма / количество для каждой unit.
- `−` *method* — При расчёте долей вычисляйте для каждой группы (числитель/сумма всех); не отказывайте, даже если группы имеют разные объёмы данных.
- `−` *method* — При ранжировании убедитесь что N верное; отсортируйте по правильному полю по убыванию, отберите ровно N элементов с наивысшими значениями.
- `−` *method* — Получите все записи всех категорий через API; убедитесь что pagination не обрезал результаты; для каждой категории отдельно посчитайте элементы.

**after epoch 6**
- `+` *method* — При расчете доли проверьте, что числитель и знаменатель из одного набора данных; убедитесь в полноте выборки по категориям.
- `+` *method* — При группировке убедитесь, что используются одинаковые фильтры для всех групп и ни одна не пропущена; проверьте согласованность данных.
- `+` *method* — При неоднозначности вопроса интерпретируйте из контекста; выполните запрос по вероятному смыслу, верните результат.
- `−` *pitfall* — Сначала попытайтесь получить данные через API-запрос; отказывайте только если API явно вернул ошибку доступа, а не по предположению о недоступности.

**after epoch 7**
- `+` *pitfall* — Не отказывайте на вопросы, пока не попробуете выполнить запрос; даже если вопрос кажется неясным или запрещенным, составьте запрос и выполните его.
- `+` *api_mechanic* — При получении результатов убедитесь, что все данные полностью извлечены через API: проверьте пагинацию, лимиты и фильтры, чтобы не потерять элементы выборки.
- `+` *method* — При контроле доступа попытайтесь выполнить запрос; если заблокирован, ответьте об ограничении явно, не отказывайте молча.
