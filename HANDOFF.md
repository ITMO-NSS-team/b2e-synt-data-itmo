## 1. Что это

Генератор синтетического HR-корпуса **в форме API Heimdall**. Нужен как
инструмент для симуляционных экспериментов с B2E-агентом — низкоресурсной LLM
(уровня Haiku 4.5, окно ~200k), которая помогает сотруднику и при этом:

* **не может генерировать и исполнять код в рантайме** (требование ИБ);
* исполняет только предопределённый код, приложенный к скиллу;
* получает данные исключительно через ответы API;
* должна уметь понять, что нужен новый скилл, и написать его вместе с кодом —
  исполнимым в следующей сессии.

Корпус — не результат, а измерительный прибор. Исследовательские вопросы и то,
какое свойство корпуса делает каждый из них измеримым, — в
[`docs/research-agenda.md`](docs/research-agenda.md).

## 4. Что надо знать про устройство, прежде чем менять код

**Витрина — проекция, а не генератор.** Есть одна популяция; любая колонка
проходит цепочку в `b2e/gen/resolve.py`:

```
переопределение витрины (frame.extra)
  → атрибут человека по алиасу        ← таблица _build_aliases(), правьте её
  → атрибут оргединицы по уровню      ← регулярки _ORG_LEVEL / _ORG_CHIEF
  → группа массивов                   ← _DOTTED и _EDU_FLAT
  → процедурный заполнитель по имени  ← b2e/gen/fillers.py
  → процедурный заполнитель по типу
```

Хотите, чтобы колонка перестала быть шумом, — добавьте алиас, а не правьте
витрину. Один алиас чинит класс колонок сразу на всех 37 витринах.

**Гибридное хранилище.** На диск идут только колонки, которые цепочка знает
осмысленно (~800 из 4599). Остальные считаются на чтении из координаты
`(seed, витрина, колонка, строка)`. Поэтому:

* `TableReader._index` — что реально лежит на диске;
* `reader.available()` — что видит агент (каталожные имена целиком);
* два процесса API дают одинаковый ответ на хвостовую колонку.

**Истина отдельно.** `data*/truth/people.json` — скрытые факторы и метки. Через
API недоступны. Тест `test_latent_factors_are_not_served` следит, чтобы не
утекли.

**Каверзы переключаются.** `b2e/traps.py`, список включённых пишется в манифест
снимка. Ключ каверзы — **человек**, а не строка витрины: иначе один сотрудник
оказался бы в верхнем регистре на одной витрине и в нижнем на другой, и каверза
превратилась бы в рассогласование личности.

## 5. Состояние сборки на 300 000 человек

**Собрано и проверено** 2026-08-02 на машине с 2 ядрами и 16 ГБ ОЗУ.

```
snapshot_id  heimdall-sandbox@491982276fdc532d
seed         20260801
294 000 человек, 32 522 подразделения, 37 витрин, 435 МБ в data/
гейт         make validate — 22 проверки, 0 отказов, 0 предупреждений
правдоподобие make stats — все маргиналы и связи в заданных диапазонах
```

Первая попытка (на 4 ГБ ОЗУ) была убита OOM killer на первой же витрине.
Причина — заниженная оценка в прежней версии этого раздела: пик RSS сборки
**2,80 ГБ**, а не «около 1,1 ГБ». На 4 ГБ этого хватало ровно чтобы не хватило.

Замерено (пик RSS и время растут линейно по числу людей: ~40 МБ постоянных плюс
9,1 МБ и 5,1 с на каждую тысячу):

| человек | пик RSS | время |
|---|---|---|
| 3 000 | 67 МБ | 11 с |
| 30 000 | 313 МБ | 150 с |
| 300 000 | 2,80 ГБ | 26 мин 38 с |

Пересборка детерминирована и не инкрементальна: если процесс убит, каталог
`data/` чистится и сборка запускается заново целиком.

```bash
make data                         # сборка, ~27 мин
make validate                     # гейт
tail -f build-300k.log            # прогресс: строка на витрину
```

Численность на выходе — 294 000, а не ровно 300 000: разбиение по подразделениям
округляет, и это правильнее подгонки.

Корпус в git **не кладётся** — он воспроизводится из seed.

**Осторожно с обслуживанием полного корпуса.** На `data-small` колонка стоит
~0,27 МБ, на полном корпусе — 17,5 МБ (скаляр) и 31,7 МБ (массив). Запрос по всем
колонкам широкой витрины поднял бы ~15,8 ГБ и убил бы воркер. С 2026-08-02 такой
запрос отвергается гейтом бюджета до аллокации — см.
[docs/query-budget.md](docs/query-budget.md); при подъёме стенда на полный корпус
`mem_limit` эмулятора и `HEIMDALL_QUERY_BUDGET_BYTES` обязаны быть согласованы.

## 6. Грабли, на которые уже наступили

* **`np.array(генератор)`** молча создаёт 0-мерный объект. В `marts.py` из-за
  этого один раз получилась битая колонка.
* **numpy-скаляры не сериализуются в JSON.** Любой путь, возвращающий значения
  колонки, обязан заканчиваться `.tolist()`, иначе падение всплывёт не при
  сборке, а в ответе API. Есть тест `test_response_is_json_serialisable`.
* **Порядок в `_quantile_map`.** Индекс 0 в `ESTIMATION_MARKS` — это «A», лучшая
  оценка; она достаётся *наибольшей* скрытой результативности. Прямое
  отображение переворачивает шкалу, и связь оценки с грейдом становится
  отрицательной. Уже ловили.
* **Производительность.** Всё, что делает numpy-вызов на человека, убивает
  сборку на 300 000. Ссылки на людей считаются массивом один раз
  (`Resolver._refs`), цепочка руководителей — на уникальное подразделение,
  свёртки блоков — через `bincount`. Не возвращайте поэлементные циклы.
* **Маршруты эмулятора** — REST-подобные: `POST /api/v1/mcp/query/`,
  `GET /api/v1/mcp/models/`. JSON-RPC на `/mcp` нет; `/api/v2/mcp/` несёт только
  `overview` и `skills`.
* **`make serve`** требует `python-multipart` (уже стоит в `.venv`).

## 7. С чего начинать следующую задачу

Порядок из `docs/roadmap.md`, стадии S8–S12. Первое, что нужно любому
эксперименту:

1. **S8 — gold-метки** под пять семейств задач (сравнение сотрудников, подбор
   под вакансию, готовность к росту, ключевые сотрудники, анализ команды).
   Считать **чистой функцией от популяции**, а не от витрин: иначе ошибка
   проекции попадёт и в эталон. Место — новый модуль рядом с `b2e/build.py`,
   писать в `truth/`.
2. **S9 — корзина вопросов**: 120–200 на семейство, с парафразами. Обязательны
   категории «вне зоны ответственности», «неоднозначные», «данных нет»,
   «контроль доступа», «prompt injection» — без них измеряется точность, но не
   осторожность.
3. **S10 — скоринг**: детерминированные проверки там, где ответ формален;
   рубрика для агента-оценщика там, где текст. Отдельно измерять расхождение
   «лайк vs правильно».
4. **S11 — харнесс B2E**: запрет кодогенерации обеспечивает харнесс, а не
   промпт.
5. **S12 — контур рефлексии** на трассах флота.

Полезные зацепки, уже заложенные в корпус: `stable.agentic_skill_level` — шесть
ступеней владения ИИ-инструментами (готовая ось сегментации пользователей);
`dm_special.talent_radar_people` — 10% профилей зеркалят сотрудников под другим
ключом (вопрос про перенос памяти между системами); `_dep`-копии покрывают 82%
людей (устаревшая реплика неполна — наблюдаемое свойство).

## 9. Безопасность

* **PAT, выданный в чате, скомпрометирован.** Отозвать:
  https://github.com/settings/tokens. В файлы и коммиты он не попадал —
  использовался только через переменную окружения.
* **Репозиторий публичный** и раскрывает таксономию витрин и колонок Heimdall.
  Сырая спецификация OpenAPI в git не попала (`.gitignore`), но производный
  каталог — да, иначе код не работает. Сделать приватным:

  ```bash
  curl -X PATCH https://api.github.com/repos/Mosyamac2/b2e-synt-data \
    -H "Authorization: Bearer <новый PAT>" -d '{"private":true}'
  ```
* Данные полностью синтетические, словари написаны вручную; совпадения с
  реальными людьми исключены.
