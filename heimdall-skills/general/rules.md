# Общие правила канала

## Поля тела запроса

Обязательны `schema` и `logic_model`. Полный набор: `columns`, `filters`, `limit`, `limit_by`, `logic_model`, `metrics`, `offset`, `order_by`, `param_columns`, `param_metrics`, `schema`, `time_dimensions`.

Любое поле вне этого списка отвергает тело целиком.

## Чего через канал сделать нельзя

Это границы возможностей, а не временные ограничения. Ни один рецепт не должен
обещать выход за них.

- **Состояния ровно на одну дату** нет. У актуальных витрин есть только
  «сейчас», у исторических — окно `[from, to)` с шагом периода.
- **Сравнить два датированных среза** нельзя: год к году через канал не
  выражается.
- **Произвольных агрегатов нет.** Доступны только метрики каталога;
  `avg(...)` по любой колонке посчитать нельзя.
- **Внутренние поля `Array(Tuple)` и `Array(Map)`** можно только вывести, но
  не отфильтровать и не сгруппировать.
- **JOIN между витринами не поддержан.** Соединение данных двух моделей —
  задача пост-обработки на стороне агента.

Если задача требует чего-то из этого, скажите об этом прямо и предложите
обходной путь. Приблизительный ответ, выданный за точный, хуже отказа.

## Массивы

Больше половины колонок крупных витрин — массивы. Массивы одного блока
(`goals.*`, `estimation.*`, `absence.*`) выровнены **позиционно**: i-й элемент
одного относится к i-му элементу остальных. Читать их независимо нельзя.

Если у блока есть скалярный предагрегат — берите его. `mean_value_completion`,
`num_goals` и `risked_goals` заменяют двадцать пять массивов `goal_*`.

## Устаревшие копии

Витрины с суффиксом `_dep` — устаревшие копии с отстающим срезом данных.
Новые запросы на них направлять не нужно.

Поиск готового рецепта под задачу: `find_skills("<задача>")`. Обзор доменов и приёмов: `get_overview()`.
