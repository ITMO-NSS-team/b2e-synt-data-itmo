# Лимиты и пагинация

`limit` по умолчанию 100, потолок канала — **1000**.

## Ужатие происходит молча

Значение выше потолка **не даёт ошибки**: оно тихо ужимается до
1000. Узнать об этом можно только по полю `limit` в ответе —
там лежит применённое значение, а не запрошенное.

Отсюда правило: если пришло ровно 1000 строк, считайте, что данные
обрезаны, и продолжайте выборку.

## Постраничный обход

```json
{
  "schema": "dm_core",
  "logic_model": "employee_actual",
  "columns": [
    "person_id",
    "employee_full_name"
  ],
  "order_by": [
    {
      "field": "person_id",
      "kind": "column",
      "direction": "asc"
    }
  ],
  "limit": 1000,
  "offset": 1000
}
```

Признак `has_next_page` в ответе говорит, есть ли ещё страницы.

**Стабильная пагинация требует детерминированной сортировки.** Без `order_by`
порядок строк произвольный, и страницы могут пересечься или пропустить записи.

## Не делайте выводов по усечённой выборке

Если `has_next_page` равно `true`, вы видите часть данных. Ответ «в
подразделении три сотрудника», построенный на первой странице, будет неверным.
Либо доберите страницы, либо посчитайте метрикой в режиме агрегата.

## Стоимость запроса

Ширина выборки стоит денег: витрины широкие, и запрос на сто колонок дороже
запроса на пять. Запрашивайте только то, что используете.

В истории стоимость примерно равна «периоды × сущности».
