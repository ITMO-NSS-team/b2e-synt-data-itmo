# Скиллы канала v2

Каталог скиллов эмулятора: то, что B2E-агент получает через `find_skills`,
`get_skill` и `get_docs`. Два вида, по расширению файла.

**Приём** (`.md`, `kind: reference`) объясняет механизм канала: пагинацию,
агрегаты, дерево фильтров, коды ошибок. Формат — YAML-frontmatter плюс текст.

**Рецепт** (`.yaml`, `kind: recipe`) отвечает на конкретный кадровый вопрос
готовым телом `mcp_query`. Поле `query` подаётся агенту как «исполняется как
есть»; меняются только поля, перечисленные в `params`.

```
general/     приёмы: контракт канала
org/         численность и оргструктура
succession/  преемники и кадровый резерв
talent/      оценки и компетенции
attrition/   признаки модели оттока
```

## Почему каталог не пуст

Пустой каталог допустим — витрины отвечают и без скиллов, и это один из режимов
эксперимента. Но значением по умолчанию он быть перестал, и вот почему.

Пока здесь лежал один README, `get_docs` возвращал заглушку в полсотни
символов, `find_skills` — пустоту, а `get_overview` — 943 символа без единого
упоминания лимитов. На вопрос «сколько мужчин и женщин работают в компании»
агент выдал «618 и 382, всего 1000» по корпусу в 294 000 человек: он вычитал
одну страницу и принял её за компанию. API при этом был честен — в конверте
лежал `has_next_page: true`.

Чтобы вернуть пустой режим, укажите `HEIMDALL_SKILLS` на пустой каталог. Это
условие эксперимента, и его стоит записать в протокол прогона.

## Правило для новых файлов

Каждый пример обязан исполняться. `make check-docs` берёт все фенсы
` ```json ` из приёмов и все `query` из рецептов и отправляет их живому
эмулятору; документ, обещающий то, чего API не делает, заводит агента в отказ,
который тот не может продиагностировать.

Пример, который принципиально нельзя выполнить как есть — скажем, векторный
поиск, которому нужны 384 числа, — оформляется как ` ```jsonc ` и снабжается
оговоркой в тексте. Язык ограды и есть признак: `json` значит «это работает»,
`jsonc` значит «это схема».
